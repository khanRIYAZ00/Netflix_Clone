# Netflix Clone

A Netflix-inspired streaming UI built with React and Vite. This project recreates the feel of a modern streaming app: a cinematic hero section, category rows, search, movie detail modal, My List behavior, and a demo playback view. The app pulls live metadata from The Movie Database (TMDB) API and presents it in a Netflix-style interface.

This is a frontend-only demo. It does not stream movies or provide a real backend, authentication system, or subscription logic. The player screen is intentionally a UI mockup, and the media content is sourced from TMDB.

## Live Demo / Project Goal

The goal of the project is to provide a polished front-end clone of Netflix's browsing experience while demonstrating:

- React component-based UI composition
- API-driven catalog loading
- Search and content filtering
- Responsive navigation and layout
- Modal-based movie detail views
- Local persistence with browser storage
- Clean design inspired by streaming platforms

## Tech Stack

- React 18
- Vite 6
- JavaScript (ES modules)
- CSS for all styling and responsive design
- TMDB API for movie and TV metadata
- Lucide React for icons
- Browser localStorage for saved “My List” items

## Architecture Overview

The project follows a simple component-driven structure:

- App-level state orchestrates navigation, data loading, search, modals, and saved list items
- API utilities centralize TMDB requests and result shaping
- Reusable UI components render row cards, headers, hero banners, and modals
- Page-level components render search, help/settings, and player screens
- A single global stylesheet manages the Netflix-like visual language

### High-level flow

```text
Browser UI
  ├─ Header / navigation
  ├─ Hero section
  ├─ Movie rows
  ├─ Search results page
  ├─ Detail modal
  └─ Player page
        │
        ▼
   App.jsx state
        │
        ├─ loadCatalog() -> TMDB API
        ├─ searchCatalog() -> TMDB search endpoint
        └─ localStorage -> saved titles
```

## Detailed File-by-File Explanation

### Root Files

#### `package.json`
Defines the project metadata and scripts:

- `npm install` installs dependencies
- `npm run dev` or `npm start` starts the Vite development server
- `npm run build` creates the production bundle
- `npm run preview` serves the production build locally

Dependencies include:

- `react` and `react-dom` for UI rendering
- `lucide-react` for icons
- `vite` and `@vitejs/plugin-react` for the development/build toolchain

#### `index.html`
This is the main HTML shell for the app. It contains the root mount element:

```html
<div id="root"></div>
```

Vite loads `src/main.jsx` as the module script, which renders the React app into the DOM.

#### `.env.example`
Template for required environment configuration. It defines:

```dotenv
VITE_TMDB_TOKEN=your_tmdb_api_read_access_token_here
```

The application reads this value from `import.meta.env.VITE_TMDB_TOKEN` in `src/api.js`.

#### `.env`
Your local environment file. It should contain your actual TMDB Read Access Token. This file is not usually committed to version control and is required before running the app.

#### `public/favicon.svg`
Simple browser tab icon with a minimal Netflix-inspired look used in the browser tab.

#### `dist/`
Generated production build folder created by Vite. It is not typically edited by hand and contains the optimized bundled JavaScript and CSS for deployment.

### Source Entry Files

#### `src/main.jsx`
Application bootstrap file.

Responsibilities:

- Imports React and `createRoot`
- Imports the main application component from `App.jsx`
- Imports global styles from `styles.css`
- Renders the entire app under `#root`

#### `src/App.jsx`
This is the central state and flow controller for the app. It manages the Netflix-like experience and orchestrates the entire front-end behavior.

Key responsibilities:

- Loads the movie catalog from TMDB
- Stores the catalog in state
- Handles search queries and debounced TMDB search requests
- Tracks the active page (`Home`, `Movies`, `TV Shows`, etc.)
- Tracks selected movie details for the modal
- Maintains a browser-saved “My List” array
- Handles open/close behavior for the detail modal and player page
- Displays loading and error states if the API fails
- Renders the header, hero, rows, search page, and footer

It also defines the app navigation flow and the `toggleList` logic for saving/removing titles from the user’s list.

Features implemented here:

- Catalog fetch on initial load
- Search across all media types (movie, TV, etc.)
- Debounced requests to reduce request frequency
- Save/remove from My List stored in `localStorage`
- Page sections like Trending, Top Rated, etc.

#### `src/api.js`
This is the API layer connecting the app to TMDB.

Responsibilities:

- Defines the base TMDB URL and image host
- Reads the token from `VITE_TMDB_TOKEN`
- Builds image URLs using TMDB poster paths
- Normalizes API results into app-friendly objects
- Fetches catalog rows for different sections
- Performs search queries against TMDB

Important functions:

- `imageUrl(path, size = 'w500')`
  - Returns a full TMDB image URL based on the poster/backdrop path

- `normalize(item, type)`
  - Converts raw TMDB objects into a consistent shape with fields such as:
    - `id`
    - `type`
    - `title`
    - `year`
    - `rating`
    - `poster`
    - `backdrop`
    - `overview`

- `request(path)`
  - Performs authorized TMDB API fetches using the bearer token

- `loadCatalog()`
  - Fetches home-page catalog groups like:
    - Trending
    - Movies
    - TV Shows
    - Top Rated
    - New Releases

- `searchCatalog(query)`
  - Performs multi-search across movies and TV content using the TMDB search endpoint

The app expects the token to be valid and the internet connection to be available.

## State and Data Flow

The app uses React state to drive its behavior:

- `catalog`: fetched TMDB categories
- `page`: current route or browsing page
- `selected`: currently opened title details
- `query`: current search input
- `searchResults`: live search results
- `list`: saved titles in My List
- `playing`: whether the demo player is active
- `apiError` and `apiStatus`: loading/error states

### Local persistence

The app stores the user’s My List in `localStorage` under the key `netflix-list`.

That means:

- user-added titles remain saved between refreshes
- the app preserves the browsing experience without a backend

## How the App Works

1. On initial page load, `App.jsx` calls `loadCatalog()`
2. `api.js` requests movie and TV data from TMDB using the VITE_TMDB_TOKEN
3. The returned objects are normalized into a single data shape
4. Rows such as Trending, Popular Movies, and TV Shows are rendered
5. User can click any poster to open the detail modal
6. User can search for titles; requests are debounced and sent to TMDB
7. User can save a title to My List and the list persists in localStorage
8. Player page is a mock UI demonstration and does not play real video

## Setup Instructions

### Prerequisites

- Node.js 18 or newer

- A TMDB API Read Access Token

1. Clone the repository
2. Open the project folder

5. Install dependencies:

```bash
npm install
```

6. Start the Vite dev server:

```bash
npm run dev
```

Or alternatively:

```bash
npm start
```

Then open the local URL shown in the terminal, usually:

## Environment and API Notes

This project depends on TMDB for its catalog data.

You must provide a valid token with read access to TMDB, or the app will show a loading/error state. The app uses `fetch` to make requests to the TMDB API with the Authorization header:

```javascript
Authorization: Bearer ${TOKEN}
```

### Why the token is required

TMDB does not allow public access to all trending and catalog data without authentication, so the app relies on a user-provided token in `.env`.

## Known Limitations

- No real streaming or video playback backend
- No real authentication or user accounts
- No backend database or server-side logic
- Only a front-end demowork; some UI actions are intentionally simulated
- Search and content depend on TMDB availability and rate limits
- Styling is custom and may not be pixel-identical to the real Netflix app

## Best Practices and Design Notes

- Componentized architecture keeps logic modular and reusable
- API logic is isolated from UI logic
- State is centralized in `App.jsx` for easier maintenance
- localStorage is used intentionally to provide a lightweight “save list” feature without a backend
- CSS is global and intentionally themed to mimic Netflix design patterns
